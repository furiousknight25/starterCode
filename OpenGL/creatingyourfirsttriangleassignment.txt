    glGetString, glEnable, glDepthFunc, glClearColor, glViewport, glGetIntegerv, glGenBuffers, glBindBuffer, glBufferData, glGenVertexArrays, glBindVertexArray, glEnableVertexAttribArray, glVertexAttribPointer, glClear, glDrawArrays, glDeleteBuffers, glDeleteVertexArrays
    
    whats the point of having gl and glfw sepperated?
    GLFW handles creating the OS window, listening for keyboard/mouse inputs, and creating the OpenGL context, while OpenGL does the actual 3D rendering and GPU commands inside that window. Separating them keeps OpenGL portable so it doesnt have to deal with OS-specific window management.
Q: What part of the shading system is doing the barycentric interpolation of color for you?
    The rasterizer (rasterization stage) between the vertex shader and the fragment shader. Any vertex attribute passed out of the vertex shader to the fragment shader gets automatically barycentrically interpolated across the triangle by the fixed-function rasterizer hardware.

Q: Why is programming OpenGL considered heterogeneous multiprocessing and what does that mean to you?
    It is heterogeneous multiprocessing because the program executes across two completely different processors with different architectures: the CPU (host) and the GPU (device). The CPU handles sequential logic, window events, and setup in C++, while the GPU runs massive parallel shader stages (vertex and fragment shaders) on thousands of cores at once. To me, it means I have to write code for both the host and device, explicitly manage moving vertex data over the bus into GPU memory (VBOs), and coordinate shader execution.
