All Shapes Have a Shader

One other component you will need to consider is that all Shapes in our renderers will need a Shader. So, you will want to likely modify your shapes to either contain a default Shader if none is given (normal shader might be a good choice here), or allow you to set a Shader (std::shared_ptr<Shader>) with some set function. That way you can instance a Lambertian shader and provide it to one of your Spheres.

 
Hit Structure is Needed

You will also need to make sure you have the HitStructure (or HitRecord) in place. The slides from Tuesday have some information on what you minimally need in your Hit Structure.

 
Point Light

For these very basic shaders, we need to know the direction to a single light from the point of intersection.  To compute this, you will need some notion of a Point Light in your Scene class so you can query its position (a simple vec3). We can assume the point light's color is white for now (1,1,1).  So, be sure to store in your Scene a Point Light. You are also welcome to hard-code the Point Light for this lab while you are testing Shading out. If you do hard-code the light position into each shader, I would set the position to something like (0, 10, 5) so the light is above and slightly behind the default camera.

Lambertian

The basic Lambertian shading approximation simply does a dot product between the normal vector and the direction the light. That is it!  However, one gotcha is that if the dot product is negative, the surface is NOT being lit, so you better return 0 then!  Something like this will be helpful:

   float nDotl = std::max( 0.0, dot( normal, lightDir ) );
   vec3 lambertShade( nDotl, nDotl, nDotl );

If you get creative, you can simply multiple (component by component) the diffuse color of the material with the nDotl value to get nicely colored, shaded and lit shapes. You should get an image like this:

Blinn-Phong

Blinn-Phong simply ADDs a specular (shiny) component to the Lambertian component above so getting Lambertian working first would be advised.  With Blinn-Phong, you need to compute a half-vector which is simply the vector that combines the view direction (where the ray came from) and the light direction.  The half-vector is then dotted with the normal vector to determine how "shiny" or how large of a specular highlight we might apply.  We raise that dot product to the Phong exponent using the std::pow function.  The larger the Phong Exponent, the tighter and smaller the specular highlight. For example, your Blinn-Phong color will be something like this computation:

  lambertianComponent + std::pow( std::max(0.0, normal.dot(halfVector)), phongExp );

Q: How do you compute the view direction as simply as possible?

A: Just take the negative of the ray direction: view_dir = unit_vector(-r.direction()). Since the camera ray points from the eye to the intersection point, negating it points back to the camera/eye.

Lambertian rayColor:

color rayColor(const HitStructure &h) override {
    vec3 normal = unit_vector(h.normal);
    vec3 lightDir = unit_vector(light_pos - h.p);

    float nDotl = std::max(0.0, dot(normal, lightDir));
    vec3 lambertShade(nDotl, nDotl, nDotl);

    return diffuse_color * lambertShade;
}

Blinn-Phong rayColor:

color rayColor(const HitStructure &h) override {
    vec3 normal = unit_vector(h.normal);
    vec3 lightDir = unit_vector(light_pos - h.p);
    vec3 viewDir = unit_vector(h.view_dir);

    // diffuse
    float nDotl = std::max(0.0, dot(normal, lightDir));
    color lambertianComponent = diffuse_color * nDotl;

    // specular
    vec3 halfVector = unit_vector(lightDir + viewDir);

    double spec = 0.0;
    if (nDotl > 0.0) {
        spec = std::pow(std::max(0.0, dot(normal, halfVector)), phongExp);
    }

    color specularComponent = specular_color * spec;

    return lambertianComponent + specularComponent;
}
